# 네트워크 설계

> 상태: 초안 (스캐폴딩 단계)

## 1. 호스트 네트워크 현황

| 인터페이스 | 용도 | 비고 |
|---|---|---|
| eno1 | 유선, 172.30.1.8/24 | 실사용 인터페이스 |
| wlp10s0 | 무선 | DOWN, 미사용 |

기존 Docker 기본 브리지 대역: `docker0`(172.17.0.0/16). 신규 프로젝트 네트워크와의 충돌을
피하기 위해 아래와 같이 별도 대역을 사용한다.

## 2. Docker 네트워크 대역 계획

| 네트워크명 | 대역 | 용도 |
|---|---|---|
| `frontend` | 172.20.0.0/24 | Nginx ↔ App |
| `backend` | 172.20.1.0/24 | App ↔ DB |
| `monitoring` | 172.20.2.0/24 | Prometheus ↔ 각 exporter/서비스 |

- App/DB는 `backend` 네트워크로 격리하여 외부에서 직접 접근 불가하도록 구성
- Nginx만 호스트 포트를 바인딩 (80/443)

## 3. 포트 계획

| 포트 | 용도 | 현재 상태 |
|---|---|---|
| 80/443 | Nginx (외부 진입점) | 사용 가능 (확인 완료) |
| 3000 | App (내부, Nginx가 프록시) | 사용 가능 |
| 5432 | PostgreSQL (내부 전용) | 사용 가능 |
| 9090 | Prometheus | 사용 가능 |
| 3001 | Grafana (기본 3000은 App과 충돌 방지 위해 3001 사용 검토) | 사용 가능 |
| 9100 | node-exporter | 사용 가능 |
| 8081 | cAdvisor | 사용 가능 (8080은 회피) |

> 8080은 이전 작업 컨테이너가 점유했던 이력이 있어(현재는 정리 완료) 혼동 방지를 위해 계획에서 제외.

## 4. 방화벽/보안 (추후 상세화)

- 외부 노출: 80/443, 22(SSH)만 허용 예정
- 내부 전용 포트(5432, 9090 등)는 호스트에 바인딩하지 않고 Docker 내부 네트워크로만 통신
